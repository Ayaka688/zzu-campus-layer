# 不接 API key 也能好用 —— 无模型路径改造方案

> 目标读者：维护这个扩展的人。所有数字都是「设计目标」，基线要在 Day 1 用留出集实测出来再回填。
> 现状代码以 `zzu-campus-layer-full` 的 `main`（含本地未推改动）为准。

---

## 0. 一页结论

| 想要 | 做法 | 大致成本 |
| --- | --- | --- |
| 不中的时候别给「说明书」 | 未命中返回**可点的建议 / 能力卡** | 2h |
| 用户的说法千奇百怪也能懂 | **离线说法库 + 打分匹配**（正则没中才用） | 1 天 |
| 「明天有课没」「kt」这种也能懂 | 归一化 + 拼音首字母 + 错字表 | 4h |
| 缺参数时别瞎猜 | **反问一句 + 候选按钮** | 3h |
| 点下去要秒回 | 预取 + TTL 缓存 + 空结果话术 | 4h |
| 想接模型的别被门槛挡住 | 免费服务商**预设**（默认仍关） | 2h |

三条硬约束（全程不许破）：

1. **有 key 且模型可用时，行为字节级不变**——新逻辑只挂在「无 key」或「模型失败回落」的路径上。
2. **运行时不新增网络请求**（除了本来就要调的学校接口）。说法库、词表都是仓库里的数据文件。
3. **宁可反问，不许瞎猜**。答非所问比答不出来更伤信任。

## 1. 现状：不是残废，是死胡同

读代码得到的事实：

- `src/core/agent.ts:313-317`：`ask()` 用 `canUseTools = cfg?.enabled && cfg.apiKey && resolveProvider(...).supportsTools` 分叉。
  - 有 key → `runAgent()`（function calling，模型当执行核心）。
  - 没 key → `runClassic()`；模型挂了也回落到这里（`agent.ts:319-326`）。
- `src/core/agent.ts:248-281`：`runClassic` 先 `parseIntent()`，命中就直接跑工具、**正文由模板渲染**（答案里的数字、教室、余额都是接口原值，这点比模型可信）；不命中 → `helpText(today)`。
- `src/core/intent.ts`：14 个正则分支（自习、座位、导出日历、成绩、学分、考试、服务直达、一卡通、待办、ddl、通知、课表…），全部是关键词 `test()`。
- `src/core/intent.ts:helpText()`：15 行、9 条能力的文字说明，**在 UI 里是纯文本，点不了**。
- `src/core/catalog.ts:matchServices()`：服务直达已经有 90/100 分的说法打分（服务名 + 别名包含匹配），说明「打分匹配」这条路项目里已经验证过。
- 参数抽取已有：`relativeDayOffset` / `relativeWeekOffset` / `extractPeriod` / `extractWeek` / `extractLibraryArea` / 座位号 / 服务关键词。

**结论**：无 key 时能答的那部分答得挺准（工具直出数据），问题全在「不中」的那一下——用户拿到一大段说明，既不知道该怎么改口，也点不了，于是放弃。

## 1.5 实测基线（2026-10-25，58 条口语说法）

## 2. 措施 A：不中也要「能点」（2h）

### 接口

`ToolResult` 增加可选通道（`src/core/tools.ts`）：

```ts
export interface ToolResult {
  text: string;
  data?: Record<string, unknown> & {
    /** 建议下一步：点了就等于替用户再问一次 */
    chips?: Array<{ label: string; text: string }>;
  };
}
```

### 规则

未命中时（`runClassic` 的 `!intent` 分支）返回：

1. 固定 6 张能力卡：`本周课表`、`明天有空教室吗`、`最近的通知`、`我这学期绩点`、`我卡里还有多少钱`、`打开座位预约`。
2. 再加最多 3 条「你可能是想问」：用 `suggestChips(text)` 从**说法库里挑最像的 3 条**（见措施 B），`score ≥ 0.35` 才出。

### 关键点

- chip 的 `text` 必须写成**规则一定能命中的说法**（这是让用户「学会一句话就够了」的捷径）。
- chip 不消耗任何配额、不联网。

### 验收

- `ask('我明天有课没')` → `data.chips` 含「明天有课吗」，且点击后 `via === 'rule'` 并出真实课表。
- `ask('')` / `ask('？')` → 只给能力卡，不给「你可能是想问」。
- 两个界面（`pwa/main.tsx`、`sidepanel/main.tsx`）都能渲染 chips 并点击发送，样式复用现有 `.quick` 药丸。

## 3. 措施 B：离线说法库 + 打分匹配（1 天，收益最大）

> **状态：已实现（2026-10-25）。** 实际落地：`src/core/phrases.ts`（340 条，覆盖 14 个工具）、`src/core/normalize.ts`、`src/core/utterance.ts`（`matchUtterance` / `resolveUtterance` / `suggestUtterances`）、`src/core/agent.ts` 的 `guessIntentByPhrase`（只在没配模型时走）、`test/utterance.test.ts`（31 条）。实测：64 句常见口语 **63/64** 命中正确（正则 55 + 语料补 8，两处「订座/座位图缺参数」按设计不执行）；无关的 4 句全部不执行。打分改为 `0.55×字数覆盖率 + 0.30×最大 n-gram Jaccard + 0.15×长度接近度`，阈值仍是 `0.62 / 0.42`。另外顺手修了三条正则：`明早/今晚` 的日期偏移、「图书馆还有几个座」漏判、「找个空教室写作业」被自习规则抢走。

> 本质：**用一次性的模型成本，换运行时的零成本覆盖率**。语料在开发期由模型生成、人工抽检后入库，运行时不联网。

### 数据文件 `src/core/phrases.ts`

```ts
export interface Utterance {
  /** 用户可能怎么说（归一化之后再入库） */
  text: string;
  /** 该说法对应的工具 */
  tool: ToolName;
}

export const UTTERANCES: Utterance[] = [ /* 目标 800 条 */ ];
```

- 目标规模：9 个工具 × 60~120 条；**每个工具不少于 30 条**（CI 校验，见 §7）。
- 体积：纯文本 + 工具名，gzip 后约 30KB（可以接受；不要塞进 content script，只进 background / PWA bundle）。
- 语料**只记工具，不记参数**。参数一律由现有 extractor 从用户原话重新抽——避免语料把真实输入「盖掉」。

### 生成脚本 `scripts/gen-phrases.mjs`（开发期工具）

- 输入：每个工具的描述 + 20 条种子说法（手写）。
- 用任一 OpenAI 兼容端点（本地有 key 就用，没有就让维护者填）批量扩写，去重、去重后的归一化、按工具分组写回 `phrases.ts`。
- **CI 不跑这个脚本**；产物入库、可 review、可 diff。

### 匹配 `matchUtterance(text)`（`src/core/utterance.ts`）

```ts
export interface UtteranceHit { tool: ToolName; score: number }
export function matchUtterance(text: string): UtteranceHit | null
```

打分（归一化后）：

```
score = 0.60 * 关键词覆盖率 + 0.30 * 字符三元组 Jaccard + 0.10 * 长度接近度
```

- **关键词覆盖率**：说法的「实词集」有多少出现在用户话里（去停用词后的最长公共子序列近似）。
- **三元组 Jaccard**：字符 3-gram 集合的交并比，抗语序和口气变化。
- **长度接近度**：`1 - |len差| / max(len)`，防止一句话匹配到超长说法。

阈值（两段式，宁可少答不可错答）：

| 分数 | 行为 |
| --- | --- |
| ≥ 0.62 | 直接执行该工具（`via: 'rule'`，参数照旧抽取） |
| 0.42 – 0.62 | 只作为「你可能是想问…」的候选（措施 A 的 chips），不执行 |
| < 0.42 | 当作没命中 → 能力卡 |

### 与正则的优先级（重要）

```
parseIntent() 命中  → 用正则的结论（正则更精确，且带参数意图）
parseIntent() 未中  → matchUtterance()
```

**绝不**让说法库抢走正则已经能精确处理的句子（例如「第 8 周课表」必须走 `extractWeek`）。

### 样例（12 条，展示口味）

| 明早几点的课 | get_schedule |

## 4. 措施 C：归一化与容错（4h）

`normalizeQuery(text)`（`src/core/normalize.ts`）：

1. 全角 → 半角（数字、字母、标点）。
2. 繁 → 简（**只做 200 个高频字的小表**，别引第三方库）。
3. 去语气词与句末助词：`啊/呀/呢/吧/嘛/哦/啦/了/的`（只删句末和顿号两侧，别删「的了」以外的词内字）。
4. 去标点、压空白、小写。
5. 别名替换：`图书管→图书馆`、`自习市→自习室`、`空叫室→空教室`、`基点→绩点`、`一颗卡/一卡通/饭卡/校园卡` 统一。

拼音首字母（只做 300 个高频词）：`kt→课表`、`kj→空教室`、`tz→通知`、`cj→成绩`、`kr→卡余额`、`zw→座位`、`dd→待办`…（表在 `src/core/pinyin.ts`，纯字典，无依赖）。

### 验收

以下全部命中正确工具（进 `test/normalize.test.ts`）：

`明天有课吗？` / `明天有课没` / `明早几点的课` / `kt` / `图书管还有座吗` / `绩点` 与 `基点` / `ＫＴ`（全角）/ `明天的课表啊`

## 5. 措施 D / E / F

### D 槽位反问（3h）

命中工具但缺必需槽位时，返回反问 + chips，不执行：

| 工具 | 缺什么 | 反问 |
| --- | --- | --- |
| `book_library_seat` | 座位号 | 「要订哪个座位？给个号码（例：A12）」+ chips「A12 是蒙的，先看座位图」 |
| `book_library_seat` | 日期/楼 | 「哪天、哪一层？」+ chips「今天一楼」「明天二楼」 |
| `find_free_room` | 时间 | 「哪个时段？」+ chips「明天上午」「明天下午」「现在」 |

验收：3 条单测；缺参时 `data.chips` 非空且 `tool` 不出结果。

### E 预取 + 缓存 + 空结果话术（4h）

- KV 缓存 TTL：`term` 10min、`courses` 10min、`notices` 5min、`card` 2min（键带 token 指纹，换登录态自动失效）。
- `warmup(session)`：进界面时并发预取（**有 token 才拉**，没 token 直接跳过）。
- 空结果模板（必须带 chips）：

| 场景 | 文案 |
| --- | --- |
| 那天没课 | 「2026-10-26（第 8 周）没有课。」+「看本周课表」 |
| 空教室全满 | 「这个时段全校教室都占着。」+「换到下午」「明天再看」 |

验收：缓存命中时 chip → 出结果 < 300ms（本机测）；所有空结果都有 chips。

### F 免费模型引导（2h，默认仍关）

设置页把三条免费路子做成**预设卡**（只留一个 key 输入框）：

| 预设 | 说明 |
| --- | --- |
| 硅基流动（免费档） | OpenAI 兼容，注册送额度，手机可用 |
| 智谱 GLM-4-Flash | 免费档，速度快 |
| 学校 DS-R1 | `http://chat.zzu.edu.cn`，**仅校园网**，HTTP 明文，判定一次 11~18 秒（见 `docs/school-llm-evaluation.md`） |

另外：模型报错时，在答案末尾补一行小字「这次是规则回答的（原因：…）」，别静默降级——用户得知道刚才发生了什么。

## 6. 评测怎么做

1. **留出集** `test/fixtures/utterances-holdout.json`：200 条，**不参与语料生成**，人工写过一遍。分布按真实场景配比：课表 60、空教室 40、通知 30、成绩/学分/卡 30、座位/自习 20、服务直达 20。
2. **基线**：先用**当前** `parseIntent` 跑一遍（§1.5 的 58 条只是一个起点，正式集要 200 条、更脏：带错字、语音转写、半句话、多意图混说）。要记录四个数——命中率 / 工具正确率 / 参数正确率 / 误判率。
3. `scripts/eval-no-key.mjs`：输出一张表——命中率 / 参数正确率 / 误判率 / 平均耗时 / 失败样例。
4. **回归门禁**：命中率不得低于上一次记录（写进 `docs/no-key-baseline.md`）。

## 7. 不影响已配 key 的人（怎么证明）

代码位置保证：

- 新逻辑只出现在 `runClassic()` 内、`parseIntent()` 返回 `null` 之后；`runAgent()` 一行不动。
- chips 只是 `data` 上的**附加字段**，`runAgent` 的提示词与工具循环不读它。

测试保证（`test/agent.test.ts` 加 3 条）：

1. 配 key 且 `supportsTools` → `runAgent` 被调用，`runClassic` **未被调用**（spy）。
2. 配 key 但模型 401 → 回落 `runClassic`（现状保留，`llmError` 带原因）。
3. 无 key → `matchUtterance` 被调用且 `via === 'rule'`。

体积保证：`phrases.ts` 只被 `background` 和 `pwa` 入口引用，不进 `public/content/*`（content script 体积不变）。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 说法库抢走正则的精确结论 | 正则**永远优先**；语料只在 `parseIntent() === null` 时参与 |
| 误答比不答更伤 | 两段阈值（0.62 执行 / 0.42 只当候选）；误判率进门禁 |
| 语料膨胀、维护成本高 | 只存 `text + tool`；CI 校验「每个工具 ≥ 30 条、新增工具必须补语料」 |
| 手机端首屏变慢 | 语料只进 background/PWA 包；懒加载（首次 miss 才载入） |
| 免费服务商政策变化 | 预设只是「填好 baseURL/模型的表单」，不写死额度与宣传文案 |

## 10. 明确不做

| 想法 | 为什么不做 |
| --- | --- |
| 内置一个公共 API key | 成本无底、必被滥用、泄露即全网可刷 |
| 浏览器里跑小模型（0.5B GGUF / transformers.js） | PWA 体积 +300MB 起，手机发热发烫，首次加载分钟级；吃力不讨好 |
| 自建代理转发 | 没有服务器、要碰用户数据、维护成本高 |
| 把「不接 key」做成隐藏的降级模式 | 反过来做：**无 key 是主路径**，有 key 是加分项 |
