# 通知总入口（Notice Hub）：思路与落地

> 目标：学生不再「跨群聊 / 官网 / 公众号 / 教务系统」翻通知。一次订阅，六类自动分类，截止前主动提醒，点开就是一张能读的卡。
>
> 约束（按你的要求，一条没碰）：不新建数据源、不重构框架、不碰登录接口。全部复用现有 `CampusService.notices()` 的两个来源。

---

## 0. 先看数据长什么样，再谈方案

方案好看不好用，通常是因为没看接口。实测两条来源（`test/fixtures/portal-notices.json`、`jwxt-notices.json`）：

| 字段 | 门户 CMS（`portal-cms`） | 教务（`jwxt-notice`） | 结论 |
| --- | --- | --- | --- |
| 标题 | ✅ | ✅ | 分类的主要依据 |
| 正文 | ⚠️ 服务端**硬截断 200 字** | ✅ 完整 HTML | 时间/地点能不能抽出来，几乎全看有没有教务那条 |
| 原文链接 | ✅ `url` | ❌ 没有公开链接 | 「跳转原文」只有门户能做，教务只能面板内读全文 |
| 发布时间 | ✅ | ✅ | 排序主键 |
| 来源部门 | ✅ | ✅ | 卡片副标题 |
| 活动开始时间 | ❌ 无字段 | ❌ 无字段 | 只能从正文抽，**抽不到就是抽不到** |
| 报名截止 | ❌ 无字段 | ❌ 无字段 | 同上 |
| 地点 | ❌ 无字段 | ❌ 无字段 | 同上 |

三条硬结论，直接决定了后面的设计：

1. **不能承诺「今天有 2 场讲座」这种绝对数。** 讲座时间只写在正文里；门户那条还被截断，经常连日期都落在 200 字之外。写死数字，演示当天就可能打脸。
   → 今日卡片改成**可解释口径**：今天开讲（抽到了才算）· 今天截止 · 3 天内截止 · 今天新发。每个数字后面都跟「条/个」，空的时候说「今天没有新的……」，不写「0 场」。
2. **截止日 / 地点必须「抽到才显示」。** 宁可卡片上少一行，也不要猜一个楼号——学生真的会跑错楼。抽取结果一律当**线索**，不是事实。
3. **去重是刚需，不是优化。** 同一场讲座，教务处发一遍、门户转一遍，标题几乎一样、id 完全不同。不去重的话，时间线第一屏看起来就像两份不一样的公告。

## 1. 分层：三块东西，各管一件事

```
接口原样（types.ts: Notice）
        │  toCard()
        ▼
加工结果（notice.ts: NoticeCard）  ← 分类 / 时间 / 地点 / 去重 / 排序
        │
        ├── renderCards()        聊天里的一行一条（无 UI 也能用）
        ├── noticesToIcs()       导出日历（ics.ts）
        └── find_notices 工具     模型和规则层都能调
```

**为什么不在 `Notice` 上加字段**：`Notice` 是「接口给了什么就是什么」，卡片是「我们加工成什么」。混在一起以后接口一改，分类/提醒/日历全跟着崩。两层分开，改接口只动 `toCard`。

**为什么规则单独一个文件**：`noticeRules.ts` 里只有词表和正则，改得最频繁（换学期、新赛事、新叫法）。流程（去重/排序/聚合）不该跟着动。

## 2. 分类：6 类，标题权重 3 : 正文 1

`src/core/noticeRules.ts` 的 `CATEGORY_RULES`，**数组顺序就是优先级**：

| 类 | 词表（节选） | 典型标题 |
| --- | --- | --- |
| 讲座 | 讲座 / 学术报告 / 报告会 / 讲坛 / 论坛 / 沙龙 | 「名家讲坛：人工智能的未来」 |
| 比赛 | 比赛 / 竞赛 / 大赛 / 挑战杯 / 创新创业 / 数学建模 / 评奖 | 「关于举办首届 AI 智能体创新应用大赛的通知」 |
| 会议 | 会议 / 座谈会 / 研讨会 / 工作会 / 部署会 | 「关于召开学生工作会议的通知」 |
| 教务 | 选课 / 重修 / 考试 / 学分 / 培养方案 / 放假 / 报到 | 「2025-2026-2 重修报名通知」 |
| 生活 | 食堂 / 宿舍 / 停水 / 报修 / 校车 / 体检 / 图书馆 | 「关于 XX 宿舍楼停水的通知」 |
| 活动 | 活动 / 晚会 / 演出 / 运动会 / 社团 / 文化节 | 「关于举办校园文化节活动的通知」 |

打分：**标题命中 +3，正文命中 +1**。理由：标题是编辑给这条通知定的「身份」，正文里可能顺带提一句别的——讲座通知写「本次比赛由教务处主办」，不该被归到比赛。

一条都没命中 → 兜底 `academic`（教务）。学校的无名通知绝大多数是行政通知，这个兜底比硬造一个「其他」更接近学生找东西的直觉。要改就改规则表，别改流程。

### 2.1 教务再细分（学生真正找的是「选课」「考试」「成绩」）

「教务」太笼统，所以教务卡片会再挂一个子类（`ACADEMIC_TOPICS`，标题 +2 / 正文 +1，顺序即优先级）：

| 子类 | 词表（节选） |
| --- | --- |
| 选课 | 选课 / 退课 / 重修 / 补选 / 改选 / 预选 |
| 考试 | 考试 / 考场 / 监考 / 补考 / 缓考 / 重考 |
| 成绩 | 成绩 / 绩点 / 查分 / 成绩单 / 分数复核 |
| 学籍 | 学籍 / 注册 / 休学 / 复学 / 转专业 / 异动 |
| 毕业 | 毕业 / 学位 / 结业 / 离校 |
| 论文 | 论文 / 开题 / 查重 / 送审 / 盲审 |
| 实习实践 | 实习 / 实训 / 实验课 / 社会实践 |
| 培养方案 | 培养方案 / 学分 / 教学计划 / 课程设置 |
| 四六级 | 四六级 / CET / 英语等级考试 |
| 教学 | 调课 / 停课 / 补课 / 教学 / 评教 |

子类只在卡片被判成「教务」之后才算，避免把「讲座通知」分到「教学」。卡片上是 `教务` + `选课` 两个小标签；`find_notices` 可以传 `topic: "选课"` 直接筛。

**学生口语走另一条**：`categoryFromText()`。它看的是用户说的话（「今天有什么讲座」），跟看标题的 `classifyNotice()` 分开，否则「今天有讲座吗」会跟「关于举办讲座的通知」抢规则。

## 3. 时间与地点：句子级抽取，抽不到就不写

### 3.1 截止 vs 活动，必须分开认

同一份通知里通常有两个日期：

```
讲座时间：10 月 23 日 19:00        ← 活动开始
报名截止 10 月 20 日 17:00         ← 错过就没了
```

不分开的后果，实测就踩过：HTML 去标签时如果把 `</p>` 换成空格，两句会拼成一句，`取最晚日期` 就把**讲座日期当成截止日**报给你。

所以：

- `stripTags()` 把 `</p>` / `<br>` 换成**换行**，保住段落边界；
- 按 `。；！？\n` 切句，逗号**不切**（「截止 11 月 5 日，逾期不候」要留在同一句）；
- 截止日只在**带截止语义**的句子里找（截止/截至/报名/申请/提交/报送/填报/申报/登记/受理/缴费）；
- 活动时间只在**带事件语义**的句子里找（讲座/开讲/举办/举行/召开/开幕/开始/活动时间/演出）；
- 多条截止取**最晚**的（「报名 10 月 25 日」「材料 11 月 20 日」，最晚那条才是真正会错过的）；多场活动取**最早**的（第一场）。
- 时刻识别 `19:00` / `晚上 7 点` / `下午 3 点半`，统一成 `HH:mm`；只有日期没有时刻 → 算全天。
- 12 月看到的「1 月 5 日」，过去超过半年就顺延到明年（否则下学期的通知会被标成「已截止」）。

### 3.2 地点：三级降级

1. `地点：图书馆第三报告厅`（写了标签的最准）
2. `在物理馆报告厅举行`
3. `××报告厅 / 会议室 / 体育馆` 这类楼名后缀

都抽不到 → `location` 字段就不存在。**不补「待定」**，因为「待定」会被当成「已经知道了，地点待定」。

## 4. 去重：按归一化标题合并，信息取并集

```
【通知】关于举办 AI 大赛的通知  ┐
关于举办AI大赛的通知           ┴→ 归一化后都是「举办ai大赛」→ 合并成一张卡
```

归一化规则（`normalizeTitle`）：去空白 → 去括注（【】[]（）《》「」）→ 去标点 → 去开头的「通知/公告/通告/新闻」→ 去开头的「关于」→ 去结尾的「的?通知」→ 小写。

合并时取并集，不是简单保留一条：

| 字段 | 合并方式 | 为什么 |
| --- | --- | --- |
| `sources` | 去重并集 | 卡片上可以标「教务处 + 门户」 |
| `url` | 优先门户 | 教务没有链接，只有门户有 |
| `hasFullText` | 或 | 教务给的全文能读 |
| `deadline` / `eventStart` / `location` | 先到先得（有就用） | 门户被截断抽不到，教务能抽到 |
| `publishedAt` | 取较晚 | 门户是最终发布时刻 |
| `summary` | 取较长 | 信息更多 |

`id` 用 `来源:原始id`（如 `jwxt-notice:121`），已读状态靠它，不会因为合并而漂。

## 5. 排序 / 过滤 / 搜索：一切为了「别错过」和「比一眼」

**两种排序**（`sortCards`）：

- `published`（默认）：按发布时间倒序，时间线就是这样；
- `deadline`：按截止日升序，没有截止的排 `9999-12-31` 垫底。问「什么时候截止」用这个。

**时间窗**（`withinDays`，语义写死在这里，别的地方不要自己解释）：

- `0` = 只看今天（今天发布的、今天开讲的、或今天截止的）；
- `N` = 最近 N 天发布的，或今天起 N 天内开讲/截止的。

> 开讲时间也算在窗口里：否则「今天有什么讲座」会漏掉「今天开讲、三天前发布」的那条——这是本轮修掉的一个真 bug。

**搜索**（`filterCards` + `rankCards`）：不是链接列表，是卡片。命中分：

| 命中位置 | 分数 |
| --- | --- |
| 标题 | 6 |
| 分类标签（含教务子类） | 3 |
| 摘要 | 2 |
| 部门 / 地点 | 1 |

同分按发布时间倒序。关键词先过 `expandNoticeQuery()`（同义词表只有一份：问题从「比赛」扩到竞赛/大赛/挑战杯）。

搜「讲座」能命中标题写「学术报告」的，因为分类标签本身参与打分；搜「挑战杯」能命中「创新创业大赛」，因为同义词表里有。

**临近截止高亮**：`dueLabel()` 输出「今天截止 / 明天截止 / 还有 N 天 / 已截止」，UI 按 `daysLeft <= 3` 上色，`< 0` 折叠到「已截止」。

## 6. 今日卡片：写「新发几条」，不写「今天几场」

原方案写的是「今天 2 场讲座、1 个比赛即将截止」。数据不支持这个精度（见 §0）：场次只能从正文抽，门户还被截断 200 字，抽不到就会被当成「今天 0 场」——比不显示更误导。所以主指标换成接口算得准的那个：

```
新发 3 条 · 2 个今天截止 · 1 个 3 天内截止
```

对应 `todayDigest()`：

| 段 | 口径 |
| --- | --- |
| 新发 N 条 | `publishedAt` 属于今天（凌晨 4 点前算前一天） |
| N 个今天截止 | `deadline` = 今天 |
| N 个 3 天内截止 | `deadline` ∈ (今天, 今天+3] |

全空的时候输出「今天没有新通知，也没有临近截止」。

**「凌晨 4 点换日」**：`DAY_ROLLOVER_HOUR = 4`，`calendarDay()` 负责换算。凌晨 0–4 点发布的公告、结束的讲座仍算前一天——这个点学生看的是「昨晚那场」。只影响「今天」归属，卡片上显示的真实时间不变。

## 7. 订阅与提醒：1 次订阅，0 次错过

### 7.1 存什么（`src/core/noticeStore.ts`，走 `kv.ts`）

```ts
interface NoticePrefs {
  categories: NoticeCategory[]; // 订阅的类；空 = 全订阅（默认，不做选择困难）
  keywords: string[];           // 额外关注词，命中就提醒（「挑战杯」「选课」）
  readIds: string[];            // 已读卡片 id，只留最近 1000 条
  updatedAt: number;
}
```

UI 里取消最后一个分类会提示「至少留一类」：空数组的语义是「全订阅」，取消到空会变成「全看」，跟用户意图相反。

为什么不直接写进 `kv.ts`：`kv.ts` 是存储抽象（chrome.storage.local / localStorage 二选一），业务键堆进去就成杂物间。这里跟 `storage.ts` 一样，是薄封装 + 明确形状。

### 7.2 怎么提醒（`src/background/index.ts` 的 `daily-watch`，已重写）

**上一版这里是错的**：`if (state.notifiedOn === today) return;` 写在 `notifiedIds` 之前，当天第二次根本跑不到，所以「按 id 去重」一行都没生效，实际仍是「一天一条、每天重推同一批」，当天新出现的截止也不会补推。

现在的口径：

1. `buildCards(svc.notices({limit: 80}))` → `dueCards(cards, today, 7)`（池子从 20 提到 80，且 `services.notices` 已按发布时间倒序，截止通知不会被挤出去）；
2. **一条截止一条系统通知**：`notice-<卡片id>`，标题带分类、正文带「截止 + 还有几天 + 地点/部门」。最多 3 条单卡，其余并成一条摘要（`notice-more-<日期>`）；
3. **同一条截止只推一次**：按卡片 id 记在 `notifiedIds`（跨天重置）；当天新出现别的截止 → 补推；
4. **出分一天只报一次**：`watch-grades-<日期>`，靠 `notifiedOn` 判断；
5. **每天最多 3 次推送**（`MAX_PUSHES_PER_DAY`），防骚扰；
6. **点通知 → 定位到那张卡**（见下）。

### 7.2.1 点通知直达卡片

```
系统通知点击 ──▶ background：parseNoticeNotification(id)
                    ├─ notice-<cardId>      → setNoticeFocus(cardId)（写进 kv）
                    ├─ 面板开着？           → runtime.sendMessage({type:'notice:focus', id})
                    └─ chrome.sidePanel.open({ windowId })
面板打开 ──▶ takeNoticeFocus()（取走即删）→ 切到时间线 → 展开对应分页/已截止组 → 滚过去 + 蓝框高亮
```

三个细节：

- **面板可能没开**，所以目标 id 先落盘（`noticeFocus`），面板启动时取走；取走即删，不会每次打开都跳。
- **`sidePanel.open()` 需要用户手势**：通知点击不保证算数，失败就静默忽略——目标 id 还在，用户下次自己打开面板照样会定位过去。
- 聚合通知（`notice-more-*` / `watch-grades-*`）没有具体卡片，只把时间线打开。

推送去重键：`notifiedOn`（日期）+ `notifiedIds`（当天已提醒的卡片 id）+ `pushesOn`（当天次数），都存在 `watch` 这个 key 里。

### 7.3 加入日历（`src/core/ics.ts` 的 `noticesToIcs`）

一条通知可能产出两个 VEVENT，因为提醒时机不同：

| 卡片有 | 事件 | 时间写法 | VALARM |
| --- | --- | --- | --- |
| 活动时间 + 时刻 | 定时事件（默认 2 小时） | `DTSTART;TZID=Asia/Shanghai:20261023T190000` | `-PT2H` |
| 活动只有日期 | 全天事件 | `DTSTART;VALUE=DATE:20261023` / `DTEND` 次日 | `-PT2H` |
| 截止日 + 时刻 | 定时事件（30 分钟） | 同上 | `-P1D` |
| 截止日只有日期 | 全天事件 | `DTSTART;VALUE=DATE` | `-P1D` |

`TZID=Asia/Shanghai` 与课表导出一致，不写 UTC，避免跨时区客户端错位。
**跨午夜会进位到次日**：23:30 的讲座 +2 小时 = 次日 01:30（`DTEND:20261103T013000`），不是当天的 01:30——否则 `DTEND` 早于 `DTSTART`，部分客户端会把这个事件丢掉。

## 8. UI：一块今日卡片、一条时间线、一个搜索框

复用现有件：`RichText`、`download`、`LlmFields`、`HoldButton`、现有 CSS 变量与 `pill/ghost/mini` 类。**不引组件库**。

```
┌─ 校园信息层 ──────────────── ⚙ ┐
│ [教务 · 29天] [门户 · 6h]        │
├────────────────────────────────┤
│ 今日 新发 3 条 · 2 个今天截止 › │  ← 今日卡片（点击进时间线）
├────────────────────────────────┤
│ 讲座 比赛 活动 会议 教务 生活  │  ← 分类 tab（只显示订阅的类，带计数）
│ [按发布] [按截止]  🔍 搜… 订阅 │  ← 排序 + 搜索 + 订阅（同一行）
├────────────────────────────────┤
│ ┌────────────────────────────┐ │
│ │ 讲座  · 10-23 19:00        │ │  ← 一张卡
│ │ 大模型与智能体前沿          │ │
│ │ 图书馆第三报告厅 · 教务部   │ │
│ │ 截止 10-20 17:00（今天截止）│ │  ← 临近截止高亮
│ │ [跳转原文] [加入日历] [已读]│ │
│ └────────────────────────────┘ │
│        加载更多（还有 35 条）   │  ← 本地分页，不重新请求
└────────────────────────────────┘
```

组件与状态（已实现，`src/ui/notice.tsx`）：

| 件 | 说明 |
| --- | --- |
| `<NoticeTodayCard/>` | 吃 `digest`，一行文案 + 箭头，点击切到时间线；无数据时显示「正在拉…」/「还没有通知数据」 |
| `<NoticeBoard/>` | 一整块：标题栏（未读数 + 刷新）、分类 tab（只显示订阅的类，带计数）、排序切换、搜索框、订阅勾选、卡片列表、加载更多 |
| 卡片 | 标题 + 分类徽标（按类着色）+ 教务子类小标签 + 开讲/截止/地点/部门 + 原文或「读全文」+「加入日历」+「标为已读」；`daysLeft<=3` 左边框变黄，已截止置灰划线，已读降透明度 |
| 教务全文 | 点「读全文」→ 面板内展开纯文本（`toPlainText` 后的 `RichText`），接口 HTML 从不进 DOM |
| 加载更多 | 一次拉 50 条进内存，首屏 15 条，点一次 +15；换 tab/搜索/排序时回到 15。**不重新请求**，因为门户固定 30 条、翻页意义不大 |
| 已截止折叠 | `splitByDeadline()` 把过了截止的单独拎出来，折到列表最底部（默认收起，显示「已截止（N）」）。不折的话「按截止」排序会把最过期的顶到最前——正好是用户最不需要的 |
| 定位高亮 | 从系统通知点进来时展开对应分页/已截止组，`scrollIntoView` + 蓝色描边（`.nb-focus`） |
| 订阅 | 勾选即存；取消最后一类时提示「至少留一类」，否则空数组语义会变成「全看」 |

数据流：

```
侧边栏 ──{type:'tool', tool:'find_notices', args:{limit:50}}──▶ background ──▶ CampusService.notices()
        ◀─────{ok, data:{cards, digest}}──────────────────────┘

侧边栏 ──{type:'notice:detail', id:'jwxt-notice:121'}──▶ background ──▶ getNoticeBody() → 纯文本
手机 PWA：没有 background，直接 runTool('find_notices') / getNoticeBody(new CampusService(session))
```

订阅与已读**不走消息**：面板本身就有 `chrome.storage.local`，直接调 `noticeStore`（手机端走 `localStorage`）。
点「原文」：门户卡片有 `url` → 新标签页打开；教务卡片没有链接 → 「读全文」在面板内展开，不假装有链接。

点「加入日历」→ `noticesToIcs([card])` → 现有 `download()`，文件名 `通知-<日期>.ics`。

搜索框放在时间线顶部而不是全局输入框：聊天框是「问」，搜索是「翻」；混在一起用户会不知道自己在干嘛。

## 10. 本轮修掉的坑（上一版遗留）

| 问题 | 修法 |
| --- | --- |
| 截止提醒去重是死逻辑（`notifiedOn === today` 早返回写在 `notifiedIds` 之前） | 删掉早返回，改成按 id 去重 + 每天最多 3 次 |
| `services.notices` 拼接后 `slice`，教务通知多时门户整段丢失 | 先按发布时间倒序再截断 |
| `daily-watch` 只取 20 条 | 提到 80 条（排序修好后就是「最新 80 条」） |
| `withinDays` 不看开讲时间，「今天有什么讲座」漏掉早发布的那条 | 时间窗把 `eventStart` 一起算 |
| intent「明天/本周」统一 7 天 | 今天 0 / 明天 1 / 本周 7 |
| 两套通知工具并存，同一句话换词就换形态 | `search_notice` 并入 `find_notices`（`keyword` + `withinDays`），删掉旧工具与旧渲染 |
| 教务太笼统 | 加 10 个子类（选课/考试/成绩/学籍/毕业/论文/实习实践/培养方案/四六级/教学），卡片带小标签，`topic` 可筛 |
| 今日卡片写「今天几场讲座」（抽取不可靠） | 改成「新发 N 条 · M 个今天截止 · K 个 3 天内截止」 |
| 时间线一屏塞满、没有翻页 | 本地分页：首屏 15 条，点「加载更多」+15 |
| 订阅取消到最后一个时点了没反应 | 提示「至少留一类」 |
| 已读上限 500 | 提到 1000 |
| ICS 跨午夜时 `DTEND` 早于 `DTSTART` | 结束时间跨天进位；「今天」的换日点改成凌晨 4 点（`DAY_ROLLOVER_HOUR`） |
| `renderNotices` / 老路径相关死代码 | 删掉；`expandQuery` 仍从 `tools.ts` 导出给测试用 |

## 12. 风险与实话

| 风险 | 会发生什么 | 怎么处理 |
| --- | --- | --- |
| 门户只能拿到 200 字 | 日期/地点常在截断之外，抽不到 | 抽不到就不显示；同一条教务也发时，去重会补上全文 |
| 时间抽取会错 | 例如「报名 10 月 25 日」被当成活动时间 | 截止/活动分句抽、分别取最晚/最早；卡片上截止与开讲分开写，错了也一眼能看出是哪一行 |
| 标题归一化误合并 | 「关于 X 的通知」与「关于 X 的补充通知」可能被合并 | 结尾只去「的?通知」，不去「补充通知」；合并只影响列表条数，信息是并集，不会丢 |
| 教务通知没有原文链接 | 点「跳转原文」没地方跳 | 面板内展开全文（有 `contentHtml`），比硬造一个 404 链接诚实 |
| 提醒重复 | 同一条截止反复推 | `notifiedIds` 按卡片 id 去重（本轮才真正生效） |
| token 过期 | 通知拉不到，页面空白 | 现有药丸已经会标红；今日卡片在无 token 时显示「先登录」，不显示空列表 |

## 13. 三个数字的校准（比赛叙事）

原口径：6 类通知 / 1 次订阅 / 0 次错过。按上面的实现，每个都能落地成可验证的句子：

- **6 类**：`CATEGORY_RULES` 六个类，`categoryCounts()` 输出 tab 计数——演示时点 tab 就能数。
- **1 次订阅**：`noticeStore` 存分类 + 关键词，之后分类、排序、提醒全自动；关掉面板再开还在（`chrome.storage.local`）。
- **0 次错过**：`dueCards()` 的截止窗口 + `noticesToIcs()` 的 `-P1D` 闹钟 + 后台 `daily-watch` 推送，三条路径任意一条生效就不会错过。

路径对比仍然是四步 vs 一步，但**要按真实链路说**：官方找一条讲座通知 = 打开门户 → 翻通知栏目 → 点进列表 → 再点正文（常常还要登录/跨域名跳转）；这边 = 打开侧边栏 → 今日卡片/搜索 → 卡片上直接看到时间地点。别把「4 步」说成「4 个网站」，会被评委追问。
